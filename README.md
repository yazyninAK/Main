# Мониторинг объявлений (mali oglasi)

Автоматическая проверка новых объявлений на https://2bike.rs/cikloberza/mali-oglasi,
фильтрация по критериям и уведомления в Telegram и на почту. Работает бесплатно
и автономно через GitHub Actions (cron), без сервера и без API сайта.

## Как это работает

1. `.github/workflows/monitor.yml` запускает `scripts/main.py` два раза в день
   (07:00 и 19:00 UTC = 09:00 и 21:00 по Белграду). Расписание меняется в
   поле `cron` этого файла — формат обычный cron (мин час * * *).
2. `scripts/scraper.py` скачивает страницу и парсит список объявлений.
3. Объявления сравниваются с `data/seen.json` (уже виденные) — новые проверяются
   по фильтрам из `config.yaml`.
4. При совпадении — уведомление в Telegram и на email через `scripts/notify.py`.
5. `data/seen.json` коммитится обратно в репозиторий, чтобы состояние сохранялось
   между запусками.

## Настройка

### 1. Критерии фильтрации

Редактируются в [`config.yaml`](config.yaml) — **прямо на GitHub**, без
скачивания репозитория: откройте файл → значок карандаша (Edit) → внесите
правки → Commit changes. Изменения подхватятся автоматически на следующей
плановой проверке, либо запустите проверку сразу вручную: вкладка **Actions
→ Monitor mali oglasi → Run workflow**.

Формат:
- `must_include` — список групп `any_of`. Объявление должно содержать хотя
  бы одно слово из **каждой** группы (группы между собой — И, слова внутри
  группы — ИЛИ). Добавить новый обязательный критерий — добавить ещё одну
  группу `any_of`. Добавить синоним к существующему — дописать строку в
  нужный `any_of`.
- `exclude_any` — стоп-слова: если встретится любое из них, объявление
  пропускается, даже если остальное совпало. Удобно отсеивать "куплю/ищу",
  запчасти и т.п.

Сравнение идёт по заголовку и полному тексту страницы объявления,
без учёта регистра.

### 2. Секреты репозитория

В настройках репозитория: **Settings → Secrets and variables → Actions → New repository secret**

| Секрет | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather |
| `TELEGRAM_CHAT_ID` | Ваш chat_id (см. ниже, как получить) |
| `GMAIL_ADDRESS` | Ваш Gmail-адрес (отправитель) |
| `GMAIL_APP_PASSWORD` | App Password Google-аккаунта (не обычный пароль) |
| `NOTIFY_EMAIL_TO` | Куда слать письма (можно тот же Gmail-адрес) |

**Telegram bot + chat_id:**
1. В Telegram: `@BotFather` → `/newbot` → получить token
2. Написать боту любое сообщение
3. Открыть `https://api.telegram.org/bot<TOKEN>/getUpdates`, найти `"chat":{"id":...}`

**Gmail App Password:**
1. Включить 2FA: https://myaccount.google.com/security
2. Создать пароль приложения: https://myaccount.google.com/apppasswords

### 3. Запуск

Workflow срабатывает автоматически по расписанию. Проверить/запустить вручную:
**Actions → Monitor mali oglasi → Run workflow**.

## Ограничения GitHub Actions (бесплатный план)

- Публичные репозитории: неограниченные минуты для cron.
- Приватные репозитории: 2000 минут/месяц бесплатно.
- Scheduled workflows автоматически отключаются, если в репозитории не было
  push более 60 дней — в этом случае нужно вручную включить workflow заново
  (Actions → workflow → Enable).
- Точность cron не гарантирована день-в-день (может быть задержка в несколько минут).

## Как работает поиск по критериям

`url` в `config.yaml` указывает сразу на отфильтрованную сайтом подкатегорию
"Električni bicikli" (`.../bicikli-6/elektricni-bicikli-13`) — это надёжнее,
чем скачивать всю категорию (5944+ объявлений) и фильтровать вручную.

Список объявлений на сайте не содержит текста описания — только заголовок,
цену и продавца. Поэтому для НОВЫХ объявлений (которых ещё нет в
`data/seen.json`) скрипт дополнительно открывает страницу самого объявления
и ищет ключевые слова из `config.yaml` (например "bosch" + "gen 5") в полном
тексте страницы. Уже виденные объявления повторно не проверяются.

Список отсортирован сайтом по дате публикации/**поднятия** (новые и
пролонгированные — сверху), поэтому скрипт подгружает страницы по 32
объявления одну за другой, пока не встретит объявление, которое уже видел
раньше (до 10 страниц за один запуск, для защиты от зависания при сбоях).

## Отсеивание поднятых/пролонгированных объявлений

Продавцы могут "поднимать" старые объявления — тогда они снова оказываются
на первой странице, хотя объявление не новое. Чтобы их не путать с
реально новыми:

- У каждого объявления есть числовой id (стабильный, не меняется при
  поднятии). Скрипт запоминает **максимальный увиденный id**
  (`max_known_id` в `data/seen.json`).
- Объявление считается по-настоящему новым, только если его id **больше**
  этого максимума. Старое поднятое объявление имеет id меньше максимума —
  оно будет пропущено, даже если раньше не встречалось скрипту.
- Первый запуск (когда `data/seen.json` ещё нет) только строит базовый
  список и запоминает текущий максимальный id — уведомления в этот раз
  не отправляются, чтобы не было лавины писем про уже существующие
  объявления.

## Статус

Селекторы проверены на реальной сохранённой странице сайта — парсер рабочий.
Требуется добавить секреты (см. выше), после чего мониторинг заработает
автоматически.
